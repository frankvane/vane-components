## 二、新旧插件 API 差距映射（迁移核心风险）

| # | 维度 | 旧版（lazy-image 内置） | 新内核 @vane/plugin-core | 差距评估与策略 |
|---|---|---|---|---|
| 1 | **priority 语义** | 数字**越小越优先**，默认 100 | 数字**越大越优先**，默认 0 | ⚠️ 语义反转。**实测 59 个插件 0 个设置插件级 priority**（仅 PriorityLoadingPlugin 的 config 里有同名字段，非插件级），源码零改动；包内 withPlugins 做 `kernelPriority = 1000 - domainPriority` 适配，保留领域语义 |
| 2 | **PluginContext 结构** | `{ src, imageState, containerRef, imageRef, isIntersecting, props, bus, config, networkInfo, deviceInfo, dimensions, performanceData, sharedData }` | `{ props, data, bus, refs, state, setState, shared, deviceInfo, forceUpdate, getSize, logger }` | ⚠️ 结构不同。**包内定义领域 Context 类型 = 内核 Context & 领域字段**，包内 withPlugins 用 `usePluginRuntime` 自建装配（内核注释许可的用法），执行钩子时传入扩展 context |
| 3 | 领域钩子 | 22 个（onBeforeLoad/onLoad/onLoadSuccess/onLoadError/onEnterViewport/onLeaveViewport/onProgress/onRetry/onSrcChange/onNetworkChange/onVisibilityChange/onResize/onInteraction/onAbort/render/renderOverlay/transformProps/onDecode/onPaint…） | 内核只定义 4 个通用钩子 + 索引签名 | ✅ 包内 `plugins/types.ts` 扩展领域钩子表；`executeHook` 泛型经索引签名可编译 |
| 4 | `render` 钩子 | 图片外层渲染（children 之后） | 无此槽位（overlay/header/footer） | ⚠️ 仅 BadgePlugin 1 处使用，迁入时改 `renderOverlay`（角标语义本就正确）；不扩充内核槽位 |
| 5 | Bus 通配符/批处理 | `*` 通配符 + raf 批处理（progress/scroll/resize） | 精简版（精确匹配） | ✅ **实测 59 个插件 0 处使用 bus.on/emit**，只有旧 withPlugins 内部桥接 progress；不迁 |
| 6 | hookFactory | 按需初始化底层实例注入 | 无 | ✅ 0 插件使用，不迁 |
| 7 | renderDeps | 精细渲染缓存（Issue #11） | 无（slots 有 try/catch 隔离） | ✅ 0 插件使用，不迁；单插件渲染隔离由内核 try/catch 保证 |
| 8 | 冲突策略 | conflictStrategy（error/warn/ignore/override） | register 重名静默替换 | ⚠️ 内核需确认/补充重名处理；P1.1 验证 |
| 9 | 热更新 | hotReload / savePluginState / getPluginState | 无 | ✅ 0 插件使用，不迁（后续按需补，记入 backlog） |
| 10 | 版本兼容 | minCoreVersion / maxCoreVersion + versionCompare | 无 | ✅ 0 插件使用；versionCompare.ts 仍随 advanced 入口导出（工具函数） |
| 11 | onProgress 桥接 | withPlugins 订阅 bus "progress" → executeHook("onProgress") | 无桥接 | ⚠️ 包内 withPlugins 重建该桥接（约 6 行） |
| 12 | ErrorBoundary | 每个插件渲染包 PluginErrorBoundary | slots try/catch（无 ErrorBoundary） | ⚠️ 已知差异：渲染期抛错由 try/catch 兜底；事件回调抛错由沙箱兜底。P2 评估是否给 composeSlots 加 ErrorBoundary |
| 13 | 增量注册 | 指纹去重增量 register/unregister | namesKey 变化时 clear + registerAll | ✅ 等价且更简单，无行为回退 |

**结论：13 项差距中，10 项零成本或低成本，2 项包内适配（priority/context），1 项内核确认（重名处理）。迁移风险可控。**

## 三、迁移后结构（源码路径 == 发布子路径）

```
packages/vane-lazy-image/
├── src/
│   ├── index.ts                              # .          完整包
│   ├── components/LazyLoadImagePlugin/
│   │   ├── LazyLoadImageCore.tsx             # Core（props 契约不变）
│   │   ├── ObserverPool.ts / constants.ts
│   │   ├── plugins/types.ts                  # 领域类型（从 @vane/plugin-core 派生）
│   │   └── withPlugins.tsx                   # 包内装配（priority 适配 + 领域 context + progress 桥接）
│   ├── custom-plugins/<XxxPlugin>/{doc.json,create.ts,index.ts}   # ./custom-plugins/XxxPlugin
│   ├── utils/{GlobalContext,LRUCache,PerformanceMonitor,versionCompare}.ts
│   ├── hooks/useLCPPreload.ts
│   └── entries/{core,plugins,advanced,monitoring}/index.ts
├── demo/  docs/  test/
└── package.json                              # peerDependencies: @vane/plugin-core + react/react-dom
```

旧 `plugins/`（PluginBus/PluginManager/PluginSandbox/DependencyResolver/FetchLoaderPlugin/PluginErrorBoundary/withPlugins）整体删除，能力由内核提供；`FetchLoaderPlugin`（fetch 加载器，被 index.ts 导出）评估后在内核或包内重建。

## 四、验收口径

1. `pnpm --filter vane-lazy-image build` 通过，exports 全部指向真实产物；
2. `pnpm --filter vane-lazy-image typecheck / test / lint` 通过（单测覆盖：priority 适配、领域 context 桥接、progress 桥接、1 个样板插件端到端）；
3. `node scripts/sync-exports.mjs && node scripts/generate-plugin-docs.mjs && node scripts/sync-readme.mjs && node scripts/check-packages.mjs` 全绿；
4. 入口体积：core ≤ 12KB、完整入口 ≤ 25KB（`vane.sizeBudgetKb` 声明）；
5. README 首屏为 `npm install vane-lazy-image` + 30 秒可跑示例（禁止 clone 仓库式安装说明）。
