# 27 · 全新创建一个组件包：端到端标准流程

> 适用仓库：`E:\react-plugin-component`（Git Bash 里是 `/e/react-plugin-component`）
> 唯一基线：`packages/templates/plugin-component`（骨架）+ `packages/templates/demo-shell`（demo 外壳）
> 本文每一条命令、每一个脚本名、每一个目录名，均取自仓库现有脚本与配置，未作推测。

---

## 读前必知：三条环境事实

1. **`pnpm` 不在 PATH**（实测 `which pnpm` 为空）。所以「脚本类」命令一律用 `node scripts/*.mjs`；
   「包内工具类」命令一律用包内 `./node_modules/.bin/<tool>`。下文中两种写法都给，`pnpm xxx` 是 `package.json` 里的别名，有 pnpm 时用别名更短。
   - 根 `node_modules/.bin` 只有：`eslint` / `tsc` / `turbo` / `changeset` / `prettier`
   - 包内 `node_modules/.bin` 才有：`vite` / `vitest` / `tsc` / `rollup`（实测 vane-sku：`vitest/2.1.9`）
2. **模板不进 workspace**（`pnpm-workspace.yaml` 里 `!packages/templates/**`）。新建包之后**必须跑一次 `pnpm install`**，否则新包没有 `node_modules`，包内一条命令都跑不起来。
3. **Windows 下 `vitest` 必须 `fileParallelism: false`**（happy-dom 多 worker 建临时目录 EPERM）。这一条已由 `@vane/vitest-config` 内置，**不要在包级 `vitest.config.ts` 里覆盖它**。

# Step 0 · 前置：命名与派系决策

## 0.1 命名（写错 `pnpm new` 当场拒绝）

包名必须匹配 `^vane-[a-z0-9]+(-[a-z0-9]+)*$`，实测三种报错：

```bash
node scripts/create-component.mjs                  # 打印用法，exit 1
node scripts/create-component.mjs vane_Bad         # 包名不合法: vane_Bad（需匹配 vane-xxx-yyy）
node scripts/create-component.mjs vane-sku         # 已存在: E:\react-plugin-component\packages\vane-sku
```

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| npm 包 | `vane-<kebab>` | `vane-table` |
| 核心组件目录 | `src/components/<Xxx>Plugin/` | `TablePlugin` |
| 核心组件 | `<Xxx>Core` | `TableCore` |
| 插件目录 | PascalCase + `Plugin` 后缀（A2 门禁正则 `^[A-Z][A-Za-z0-9]*Plugin$`） | `FadeInPlugin` |
| 插件工厂 | `create<Name>Plugin` | `createFadeInPlugin` |
| 插件 `name` 字段 | kebab-case，全局唯一 | `fade-in` |
| UMD 名 | `Vane<Xxx>` | `VaneTable` |
| CSS 变量 | `--vane-<component>-<token>` | `--vane-table-row-hover` |

## 0.2 放哪

- 发布包 → `packages/<pkg>/`
- 内部配置 → `internal/*`（build-config / eslint-config / tsconfig / vitest-config），**不要新建内部包**
- 文档 → `docs/components/<pkg>/`（包内 `docs/` 只是模板副本，不是维护地）

## 0.3 依赖派系（先拍板，影响体积门与 peer）

| 依赖 | 放哪 |
| --- | --- |
| `react` / `react-dom` | **只放 `peerDependencies`**（放进 dependencies 会被 `pnpm check` 判 FAIL：消费方双 React） |
| `vane-plugin-core` | peer 外部化派（vane-profile / vane-comment：`workspace:*`）或 devDep 内联派（vane-sku / vane-card：`devDependencies` 里 `workspace:*`，打进 dist） |
| 运行时第三方库 | `dependencies`，**同时加进 `vite.config.ts` 的 `external`** |
| 演示站用的库（react-router-dom / react-markdown 等） | **只放 `devDependencies`** |

> 模板 `package.json.tpl` 默认把 `vane-plugin-core` 放在 `peerDependencies`（`workspace:*`）。
> 若你选内联派，把它挪到 `devDependencies` 即可——两种写法在仓库里都有先例，不是漂移。

# Step 1 · 脚手架：`pnpm new` 到底做了什么

```bash
cd /e/react-plugin-component

# 有 pnpm：
pnpm new vane-table --title "数据表格" --desc "插件式 React 数据表格"

# pnpm 不在 PATH 时（等价，总是可用）：
node scripts/create-component.mjs vane-table --title "数据表格" --desc "一句话描述"

pnpm install        # 必须：模板不进 workspace，新包没有 node_modules
```

## 1.1 脚本实际做的事（`scripts/create-component.mjs`，逐条核对）

1. 复制 `packages/templates/plugin-component` → `packages/<pkg>`，**跳过 `README.md`**（README 由 `docs:sync` 生成）与 `node_modules`；
2. 递归替换 7 个占位符：`__PKG_NAME__` / `__NAME_KEBAB__` / `__NAME__` / `__UMD_NAME__` / `__BRAND__` / `__TITLE__` / `__DESC__`。
   只替换 `.json .ts .tsx .md .html .tpl` 六类文件；目录名里的 `__NAME__Plugin` 会同步改名；
   `__BRAND__` = Pascal 名的首字母；`--title` 省略时 = Pascal 名，`--desc` 省略时 = `${title}（插件式 React 组件）`；
3. `package.json.tpl` → `package.json`（占位符已在第 2 步替换完），随后删除 `.tpl`；
4. **自动跑 `scripts/sync-demo-shell.mjs`**（覆盖全部包，不止新包）生成 demo 外壳四件套；
5. 把包内 `docs/{index,api,plugins,recipes}.md` 复制到仓库级 `docs/components/<pkg>/`。

## 1.2 生成物清单（🔒 不要手改）

生成后，`docs/.vitepress/config.mts` 会**自动扫描 `docs/components/*`** 收录进侧栏与导航，不需要手改导航配置。

## 1.3 模板已经自带、你不用再做的合规项

- `sideEffects: false`、`files: ["dist"]`、`publishConfig.access: public`、`type: module`
- `peerDependencies` 含 `react` / `react-dom`（`>=16.8.0`）
- `vane.demo = { brand, subtitle, title, accent, bg }` 五项齐全（差一项 `sync-demo-shell` 会 `✗ vane.demo 不完整`）
- `vane.sizeBudgetKb: 30`（模板默认，按实测改，见 Step 9）
- `src/entries/core.ts` + `src/entries/plugins.ts`（A1 入口聚合）
- `src/index.ts` 不做 `export * from "./custom-plugins"`（A5/ADR-6）
- 插件三件套 `src/custom-plugins/ExamplePlugin/{create.tsx, doc.json, index.ts}`（A2/A3）
- `eslint.config.js` 三行标准版、`demo/src/main.tsx` 已去 StrictMode
- `demo/src/demos/{registry.ts, types.ts, DemoPage.tsx, 00-basic.tsx}` 逐项示例层

## 1.4 ⚠️ 模板没做、你必须补的四件事（踩过就懂）

| # | 事实 | 后果 | 修法（Step 2） |
| --- | --- | --- | --- |

# Step 3 · 核心实现

## 3.1 目录与入口聚合（A1 门禁：`src/entries/{core,plugins}.ts` 必须存在）

```
src/
├── index.ts                       ✍️ 根 facade：只聚合「核心 + 装配 + 类型」
├── entries/
│   ├── core.ts                    ✍️ 只要核心时导入（体积最小）
│   └── plugins.ts                 ✍️ 插件系统 + 官方插件全家桶
├── components/TablePlugin/
│   ├── TableCore.tsx              ✍️ 核心组件（薄）
│   ├── plugins/types.ts           ✍️ 领域类型 + 领域钩子（每包唯一要自己写的类型层）
│   └── index.ts                   ✍️ 组件内部桶导出
└── custom-plugins/                ✍️ 插件层（Step 4）
```

模板给的样板（`src/index.ts`）：

```ts
export { TableCore } from "./components/TablePlugin/TableCore";
export type { TableCoreProps, TableCoreRef, TableItem } from "./components/TablePlugin/plugins/types";

export { withPlugins } from "vane-plugin-core";
export type { Plugin, PluginHooks, PluginContext } from "vane-plugin-core";

export { createExamplePlugin } from "./custom-plugins/ExamplePlugin";
```

**根入口的定位（ADR-14 / ADR-6）**：只聚合「Core + 装配 + 契约类型」，**不桶导出全部插件**。
插件一律走 `vane-table/custom-plugins/XxxPlugin` 子路径按需引入——这是体积门能守住的前提。

## 3.2 入口 ↔ 子路径映射（`internal/build-config/discover-entries.mjs`）

**源码路径 == 发布子路径**，这是 exports 永远可预测的原因：

| 源码 | 发布子路径 | 产物 |
| --- | --- | --- |
| `src/index.ts` | `.` | `dist/index.js` |
| `src/entries/core.ts` | `./entries/core` | `dist/entries/core.js` |
| `src/custom-plugins/X/index.ts` | `./custom-plugins/X` | `dist/custom-plugins/X/index.js` |
| `src/presets/<name>/index.ts` | `./presets/<name>` | `dist/presets/<name>/index.js` |

> `components/` / `custom-plugins/` / `entries/` / `presets/` / `styles/` 是 `NON_ENTRY_DIRS`，
> 不会整体成为入口（`entries/*`、`custom-plugins/*`、`presets/*` 由脚本显式枚举）。
> 另外会自动补 `./custom-plugins/*` 通配与 `./style.css`（当 `src/styles/` 存在时）。

## 3.3 context 动态字段用 getter

插件 hook 里读到的动态状态（选择态、禁用集等）**用 getter 暴露实时值**，不要快照成普通字段——
否则插件拿到的是装配那一刻的旧值。这是 `vane-sku` / `vane-profile` 沉淀下来的契约。

## 3.4 核心组件的铁律

- 核心只做「渲染 + 转发生命周期」，**所有可变需求交给插件**；自检：核心能否控制在 150 行内。
- 模板 `Core.tsx` 已给出标准四件套：`forwardRef` + `useImperativeHandle`（`getContainer` / `forceUpdate` / `getSize`）+ `containerRefExternal` + `onMount/onUnmount`。
- 工厂 `createXxxSelector(plugins)` **必须在模块顶层调用**；写在渲染体内会每次渲染新建组件类型 → 重挂载丢状态。

# Step 4 · 插件三件套

## 4.1 目录与命名

```
src/custom-plugins/FadeInPlugin/
├── create.tsx   ✍️ 工厂 createFadeInPlugin（含 JSX 用 .tsx，纯逻辑用 .ts）
├── doc.json     ✍️ 机器可读文档
└── index.ts     ✍️ 桶导出 + meta 挂载
```

- 目录名必须匹配 `^[A-Z][A-Za-z0-9]*Plugin$`（A2），否则 FAIL。
- 三件套缺一即 A3 FAIL。
- 插件实现**不要放在 `src/components/<pkg>/custom-plugins/`**（A6 判「双 custom-plugins 结构」），统一放 `src/custom-plugins/`。
- `_` 开头的目录（如 `_shared`）会被扫描器跳过，适合放共享内部代码。

## 4.2 `create.tsx` 标准写法（模板原样）

```tsx
import type { PluginCreator, PluginDoc } from "vane-plugin-core";
import doc from "./doc.json";

export interface FadeInPluginConfig { duration?: number }

export const createFadeInPlugin: PluginCreator<FadeInPluginConfig> = (config = {}) => {
  const { duration = 300 } = config;
  return {
    name: "fade-in",              // kebab-case，全局唯一
    version: "0.1.0",
    description: doc.description,
    config,
    hooks: {
      /* 渲染钩子保持同步、纯净，禁止调用 React hooks */
    },
  };
};

createFadeInPlugin.meta = doc as PluginDoc;
```

> 模板用的是 `createExamplePlugin.meta = doc`；SKILL 里写的是 `Object.assign(create, { meta: doc })`，
> 两种等价，**以模板为准**。`meta` 丢了会导致 demo 插件卡内容空白。

## 4.3 `doc.json` 字段

```json
{
  "name": "FadeInPlugin",
  "description": "加载完成后淡入显示，可配置时长与缓动。",
  "since": "0.1.0",
  "tags": ["animation", "ux"],
  "config": [
    { "name": "duration", "type": "number", "default": "300", "description": "淡入时长(ms)" }
  ],
  "example": "withPlugins(Core, [createFadeInPlugin({ duration: 600 })])"
}
```

### ⚠️ `example` 与 `examples` 是**有意的双字段设计，不要当误用删掉**

- `example`：**单个用法字符串**，进文档站与 README 的代码块；
- `examples`：**可视化示例数组**（`{ name, description, src, config }`），驱动 demo 里的预览卡片。

# Step 5 · 样式与可访问性（ADR-13 与对比度）

## 5.1 ADR-13 三条硬约束

1. 样式抽到 `src/styles/tokens.css`（变量）+ `components.css`（`vc-` 前缀 class），由 `createLibConfig` 的
   `css-copy` 插件复制到 `dist/style.css`，并自动获得 `exports["./style.css"]`——**不要自己写复制逻辑**；
2. 核心保留三处内联：`position: relative`（overlay 定位依赖）、`box-sizing: border-box`、用户显式传入的 `padding` / `containerStyle`；
3. **容器必须自带 `color` 与 `background`，不许靠继承**；插件里**凡是内联了 `background` 的元素，也必须内联 `color`**。
   > 这一条是踩出来的：`.vc-card` 原本只有 `position` + `box-sizing`，`QuantityPlugin` 的 `-/+` 按钮内联了 `background:#fff` 却没内联 `color`，
   > 继承到 demo 深色外壳的浅色墨，两个按钮**完全看不见**。

`sideEffects` 相应从 `false` 改成 `["**/*.css"]`（`check-packages.mjs` 里 `isSideEffectFree` 认两种写法：
`false`，或**每一项都含 `.css`** 的数组）。带样式文件时不改，webpack/Rspack 生产构建会把 `import "pkg/style.css"` 整条摇掉。

## 5.2 不要用 opacity 压暗文字

需要「弱化」就换 token / 换实色，**不要降不透明度**。对比度体检脚本会把祖先链上的 `opacity` 逐层乘进来，
`opacity: .6` 的浅灰字会直接掉到 2.85:1。

## 5.3 门槛

| 场景 | 门槛 |
| --- | --- |
| 正文 | ≥ 4.5:1 |
| 禁用态（WCAG 1.4.3 豁免） | ≥ 3:1 |
| UI 元件（1.4.11） | ≥ 3:1 |

# Step 7 · 文档

## 7.1 四件套与生成关系

```
docs/components/<pkg>/index.md     ✍️ 唯一源（README 正文从这里来）
docs/components/<pkg>/api.md       ✍️
docs/components/<pkg>/recipes.md   ✍️
docs/components/<pkg>/plugins.md   ✍️ 手写骨架 + 🔒 AUTO-GENERATED 区块（由 doc.json 生成）
packages/<pkg>/README.md           🔒 由 pnpm docs:sync 生成，禁止手写
```

```bash
node scripts/generate-plugin-docs.mjs   # doc.json → plugins.md 表格（只替换 AUTO-GENERATED:BEGIN/END 之间）
node scripts/sync-readme.mjs            # docs/components/<pkg>/index.md → packages/<pkg>/README.md
```

- `plugins.md` 必须保留 `<!-- AUTO-GENERATED:BEGIN … -->` 与 `<!-- AUTO-GENERATED:END -->` 两行标记，否则脚本跳过并告警。
  标记行里写 `priority` 就多一列 priority（各包列可以不同，不必为某一包改生成器）。
- `sync-readme` 会自动给 README 加徽章首屏（含 `npm install <pkg>`），并把指向同目录 `.md` 的相对链接改写成
  `../../docs/components/<pkg>/<file>`——否则 GitHub/npm 上全 404。
- **文档站导航不用改**：`docs/.vitepress/config.mts` 自动扫 `docs/components/*`。

## 7.2 ⚠️ doc.json 里的子路径必须命中真实 exports

`check-packages.mjs` 会扫 `packages/<pkg>/README.md` 与 `docs/components/<pkg>/*.md`，
用正则抓 `"<pkg>/custom-plugins/<Name>"`，**若该子路径不在 package.json 的 exports 里就直接 FAIL**：
`文档引用了不存在的子路径：…`。

最常见的错法：**把「插件名」和「目录名」写混**（如写成 `custom-plugins/FadeIn` 而实际是 `custom-plugins/FadeInPlugin`）。
占位符（`XxxPlugin` / `X`）会被跳过，那是「自定义插件」示例的合法写法。

所以顺序永远是：**先 `sync:exports` → 再 `docs:plugins` → 再 `docs:sync`**。

## 7.3 文档里别写裸 HTML 标签

`generate-plugin-docs.mjs` 会转义 `<` `>` `&`：文档站 markdown 经 Vue 模板编译器处理，
裸 `<audio>` / `<img>` 会被当成真实 HTML 元素，报 `Element is missing end tag` 挂掉整站构建。

## 9.3 体积门（`check-packages.mjs`）

四个预算字段，都在 `package.json` 的 `vane` 下：

| 字段 | 口径 | 默认 |
| --- | --- | --- |
| `sizeBudgetKb` | 根入口 `dist/index.js` + 其静态引入的 chunk（按 chunk 文件**去重**）gzip | **12**（模板给 30） |
| `coreSizeBudgetKb` | `dist/core.js` 一支 | 不设 |
| `subpathBudgets` | `{ "./gallery": 20 }` —— 子路径闭包（递归相对引用，含 `../chunks`） | 不设 |
| `fullSizeBudgetKb` | `dist` 下所有 `.js` 一起去重压缩 | 不设 |

**超了怎么办（只有两条路，不许第三条）：**

1. **真减**：根入口不桶导出插件（ADR-14）、插件改走子路径、显式导入、重依赖改动态 import（ADR 里 file-preview 的 D8）；
2. **改口径 + 写 `sizeBudgetNote`**：在 note 里写清「原预算基于什么假设、实测多少、为什么该假设失效、上调到多少」。
   仓库里 6 个包都有 `sizeBudgetNote`，vane-sku 还额外写了 `sizeBudgetAlternatives`（给出回到小体积的替代路径与代价）。

> ❌ **不许静默调大数字**。`sizeBudgetNote` 是审计线索，不是遮羞布。

> 测量口径坑（已修，别退回去）：入口对同一个 chunk 可能有多条 import 语句，
> 运行时只加载一次，不去重会虚高（vane-sku 曾从 6.5KB 虚报成 11.2KB）。

> ⚠️ **体积门只在 `dist/index.js` 存在时才量**（源码里是 `if (existsSync(entry))`）。
> 而 `pnpm verify` 的链条里**没有 `build`**——新包刚建好、还没跑过 `vite build --mode lib` 时，
> `pnpm check` 会静默跳过体积门，只报包卫生项。所以**必须先 build 再 check**：

```bash
cd packages/vane-table
./node_modules/.bin/vite build --mode lib      # 产出 dist（含 d.ts）
cd /e/react-plugin-component
node scripts/check-packages.mjs                # 这时体积门才真的生效
```

## ⚠️ 访问路径是 `/<pkg>/`，不是 `/`

```
http://127.0.0.1:3350/              → 引导页（列出所有包）
http://127.0.0.1:3350/vane-table/   → 数据表格演示台   ← 尾斜杠不能省
```

所以深链与刷新都能落回本包；但目录不带尾斜杠时，页面里的 `./assets/x.js` 会解析到上一级 → 白屏。

另外：`build-demos.mjs` 会把 html 里的 `../assets/` 统一改写成 `./assets/`——
因为 vite `base: "./"` 让 html 落在 `demo-dist/demo/`、资源在 `demo-dist/assets/`，
聚合后 html 被提到 `demos/<pkg>/`，层级从「上一级」变成「同级」。**不要绕过脚本手工搬**。

`demos/` 已在 `.gitignore`，不入库。`--only` 时**不会重写引导页**（否则会把没参与构建的包从入口抹掉）。

## 11.3 npm publish 前置与命令

```bash
export HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890   # npm 直连不稳时
export CODEBUDDY_SAFE_DELETE_ENABLED=0    # prepublishOnly 会再 build 清 dist，本机策略会拦子进程删目录
npm publish --access public
```

> ⚠️ 仓库 `.npmrc` 的 registry 是 `https://registry.npmmirror.com`。
> 发 npm 必须显式切回官方源：`npm publish --registry https://registry.npmjs.org --no-git-checks`。

前置检查：`.changeset` 已写、README 首屏有 `npm install <pkg>`、`files: ["dist"]`、`npm pack` 干跑。

## 11.4 发布后复核（`npm view` 有本地缓存，不可靠）

```bash
node -e "fetch('https://registry.npmjs.org/vane-table/0.1.0').then(r=>r.json()).then(j=>console.log(j.version))"
node -e "fetch('https://registry.npmjs.org/vane-table').then(r=>r.json()).then(j=>console.log('latest=',j['dist-tags'].latest))"
```

npm 传播可能延迟数分钟，先轮询具体版本直到出现，再确认 `latest` 指向刚发版本。


# 契约冻结线

以下内容是**对外契约**，改动必须走「先改源头脚本/模板 → 跑 sync → 全量 verify → changeset 记破坏性变更」四步，
不允许就地手改：

| 冻结对象 | 真源 | 改法 |
| --- | --- | --- |
| `package.json` 的 `exports` | `src/` 目录结构 | 改 `src` → `node scripts/sync-exports.mjs` |
| `packages/<pkg>/README.md` | `docs/components/<pkg>/index.md` | 改 docs → `node scripts/sync-readme.mjs` |
| `docs/components/<pkg>/plugins.md` 的表格区 | 各插件 `doc.json` | 改 doc.json → `node scripts/generate-plugin-docs.mjs` |
| demo 外壳四件套 | `packages/templates/demo-shell/` | 改模板 → `node scripts/sync-demo-shell.mjs` |
| 新包骨架 | `packages/templates/plugin-component/` | 改模板（后续新包才生效，存量包不回填） |
| 已发布的导出符号名 | — | 发布后不改；只改文件名、保留导出别名 |
| 体积预算数字 | 实测 gzip | 真减，或改口径 + `sizeBudgetNote` 写理由 |
