# 28 · 几何体检方法（越界 / 溢出 / 贴边 / 纵向裁切）

起点是 vane-comment demo 的两张截图：「右侧白色评论卡片延伸到视口右边缘之外，正文最后一个字和时间戳
紧贴卡片右缘还被截断」「左栏插件描述贴着左边框，描述还普遍被切掉一半」。

这些全是**几何问题**。截图只能看出「挤」，看不出差的是 0.7px 还是 16px，更看不出是谁把整页撑宽了、
谁在偷偷裁字。这一轮把「看截图猜」换成「按像素量」：每处问题都给改前/改后两组数字，并且能指到
具体选择器与具体规则。

本轮实测结论（vane-comment，两页 + 5 条路由共 8 张卡）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 白卡 padding | 0px | **16px** |
| 时间戳/正文末字距白卡右缘 @1440 | 0 / 0.7px | **16 / 26.7px** |
| 勾选框距面板内容边 | 5.6px | **9.6px** |
| 插件描述纵向裁切（最大） | 69px（≈4 行，16/17 条被切） | **0**（最长 6 行完整显示） |
| 文档横向溢出 @1100/1080/1024/960 | 3 / 8 / 23 / **40** | **0 / 0 / 0 / 0** |

## 二、八个步骤（每步都有可复制代码与「为什么」）

### 2.1 视口设定：补回滚动条占掉的 15px

```js
const fr = document.getElementById("fr");
fr.style.height = "900px";          // 必须够高，页面才会出纵向滚动条
fr.style.width = W + 15 + "px";     // +15 补纵向滚动条，令 documentElement.clientWidth === W
```

**为什么**：`@media (max-width: 1080px)` 这类断点按 `innerWidth` 判，而「文档有没有横向溢出」
按 `documentElement.clientWidth` 判，两者差一个滚动条宽度（Chromium 15px）。不补这 15px，
你以为在量 1080，实际 clientWidth 只有 1065，数字对不上任何一张验收表。

**做法**：两个值都打印出来核对，差 15 就说明漏补了。

```js
console.log(win.innerWidth, doc.documentElement.clientWidth); // 例：1095 1080
```

### 2.2 导航防坑：只改 hash 不触发 `load`

```js
fr.src = "about:blank";
await new Promise((r) => (fr.onload = r));
fr.src = "/vane-comment/#/plugins";
await new Promise((r) => (fr.onload = r));
```

**为什么**：demo 用 `HashRouter`，切路由只改 hash —— 这是**同文档导航，不触发 `load` 事件**。
直接 `fr.src = "/pkg/#/b"` 后 `await onload` 会**永不 resolve**：现象是「跑完第一档就再也没输出」，
极容易被误判成 iframe 挂死（我自己第一版就误判了一次，换标签页也没用）。
先回 `about:blank` 强制整页重载，`load` 才会再触发一次。

### 2.3 等布局稳定：挂载 → 字体 → 动画，顺序不能反

```js
const w = fr.contentWindow;
for (let i = 0; i < 60 && !w.document.querySelector(".vc-comment"); i++) {
  await new Promise((r) => setTimeout(r, 50));   // 等 React 挂载
}
await w.document.fonts.ready.catch(() => {});    // 等 webfont
await new Promise((r) => setTimeout(r, 350));    // 等入场动画
```

**为什么**：
- 等挂载：SPA 首帧是空的，`querySelector` 拿不到目标元素时后面全是 `null` 崩塌。
- 等字体（**最容易漏、后果最严重**）：demo 全站用 JetBrains Mono / Chakra Petch webfont，
  字体没加载完时字符宽度完全不同，`min-content` 也随之不同 —— 溢出量会被量成 0，直接得出
  「没问题」的错误结论。dev-filepreview 用 CDP 三档复现不出 `.ledger em` 那条溢出，最可能就是这个原因，
  再加上他漏了 `#/` 这条路由（`.ledger` 只在首页）。
- 等动画：demo 有 `rise` 入场动画（`translateY(14px)`，延迟 40~260ms、时长 640ms），
  动画中途量到的 `rect` 带位移。

### 2.4 四类断言

```js
// 容器的 content-box 边界（注意：右边界要减 border 与 padding）
function contentBox(el, w) {
  const r = el.getBoundingClientRect();
  const cs = w.getComputedStyle(el);
  return {
    rect: r, cs,
    right: r.right - (parseFloat(cs.borderRightWidth) || 0) - (parseFloat(cs.paddingRight) || 0),
    left:  r.left  + (parseFloat(cs.borderLeftWidth)  || 0) + (parseFloat(cs.paddingLeft)  || 0),
  };
}

// ① 越界：子元素右缘超出容器 content-box 右边界
if (childRect.right - B.right > 0.5) escape.push(over = childRect.right - B.right);

// ② 溢出：容器自己被内容撑宽多少
const overflowX = el.scrollWidth - el.clientWidth;

// ③ 贴边：与容器 padding 边之差 < 4px（4px 是「肉眼已贴死」的经验阈值）
else if (B.right - childRect.right < 4) hug.push(gap = B.right - childRect.right);

// ④ 纵向裁切：line-clamp / overflow:hidden 把文字切掉多少
if (child.scrollHeight - child.clientHeight > 1 && cs.overflowY === "hidden")
  clipY.push(cut = child.scrollHeight - child.clientHeight);
```

**为什么这四条要分开**：它们指向完全不同的 bug。
① 是布局算错（宽度约束漏了 `min-width: 0`、`min-content` 撑破栅格）；
② 是容器内部溢出（该滚的没滚、或者子元素超宽）；
③ 是「内边距不够」这种观感问题（数值往往只有几像素，截图完全看不出来）；
④ 是**主动裁切**（`-webkit-line-clamp`），只有查 `overflowY: hidden` 才抓得到 —— 它不会让任何
元素越界，所以前三类断言对它全是瞎的。

### 2.5 取文本末字用 `Range`，不要用元素 `rect`

```js
function textInkRight(el, w) {
  let max = -1e9;
  const tw = w.document.createTreeWalker(el, w.NodeFilter.SHOW_TEXT);
  let n;
  while ((n = tw.nextNode())) {
    if (!n.textContent.trim()) continue;
    const rg = w.document.createRange();
    rg.selectNodeContents(n);                       // 只包住这一个文本节点
    for (const r of rg.getClientRects()) if (r.width) max = Math.max(max, r.right);
  }
  return max;
}
```

**为什么必须用 Range**：`<div class="vc-content">` 是 block，它的 `getBoundingClientRect().right`
**永远撑满整行**，等于容器 content-box 右缘。拿它做「距右缘多少」的减法，结果**恒等于 padding**，
于是白卡 padding 为 0 时量出来是 0（看起来「正常」），padding 改成 16 时量出来是 16 —— 你测的其实是
padding 本身，不是文字位置。这是**典型的假阴性**：元素级测量在这个指标上完全瞎。

`Range.getClientRects()` 拿的是**真实墨迹**：那一行最后一个字画到哪里。本轮正是靠它量出
「正文末字距白卡右缘只剩 **0.7px**」（1440 视口），修完是 **26.7px**。

### 2.6 溢出溯源：追 `scrollWidth > clientWidth` 链，而不是「谁超出了视口」

```js
function overflowChain(w) {
  const de = w.document.documentElement;
  const hits = [];
  for (const el of w.document.body.querySelectorAll("*")) {
    const cs = w.getComputedStyle(el);
    if (cs.display === "none" || cs.position === "fixed") continue;
    if (el.closest(".code, .guides")) continue;      // 见下：两个必须排除的干扰项
    if (el.scrollWidth - el.clientWidth > 0)
      hits.push({ sel: path(el), over: el.scrollWidth - el.clientWidth, ox: cs.overflowX });
  }
  return { docOvf: de.scrollWidth - de.clientWidth, chain: hits.slice(0, 8) };
}
```

**为什么**：只列「`rect.right > 视口宽` 的元素」会漏掉真正的元凶 —— 撑宽文档的是那条
`overflowX: visible` 的**祖先链**，而链上每一级都未必自己越界。必须按「谁的 `scrollWidth` 超过了
自己的 `clientWidth`」去找，才能从末端的叶子一路追到 `#main` 再到 `document`。

**两类必须排除的干扰项 + 一类 1px 噪声**（这类「预期内的假阳性」最耗人，第一版就被它们带偏过）：

| 干扰项 | 现象 | 为什么不是 bug |
|---|---|---|
| `position: fixed` 的装饰层（本仓的 `.guides` 栏位参考线，`left: var(--side-w); right: 0`） | 报告「越出 `#main` content-box +43.7px」 | fixed 元素不参与文档流、不产生滚动条。它会污染「越界」报告，必须在 `position === "fixed"` 处直接跳过 |
| 代码块 `div.code > pre > code` | 报告「越出容器 +201.9px」，甚至「越出视口 +168.5px」 | `.code pre` 是**故意** `overflow-x: auto` 的横向滚动区，宽代码本来就要滚。属预期，不是 bug。骨架里用 `el.closest(".code")` 整棵跳过（粗粒度、够用）；通用写法是看**祖先**的 `overflowX` 是否为 `auto`/`scroll` |
| 伪元素（本仓 `.plate::before` 的取景角标，`inset: -1px`） | 每个 `.plate` 都报 `scrollX = 1`、链首项 `+1px` | 伪元素不在 `querySelectorAll("*")` 里，但会把宿主元素的 `scrollWidth` 顶出 1px。**1px 级别的链项一律先怀疑伪元素**，大于 1px 才值得追 |

> 一段健康的结果长这样（本仓 vane-comment 实测，可见 1px 噪声与真实问题的区别）：
>
> ```
> == 1440px / | inner=1455 client=1440 | 文档横向溢出=0
>    链 div > section.hero > figure.plate.hero-demo +1 overflowX=visible   ← .plate::before
>   div#main.main > div > section.hero pad=32px/0px/32px/0px 越界=0 纵裁=0 末字留白=12
> == 1440px /plugins | 文档横向溢出=0
>   div > div.ws > aside.ws-panel  pad=12px/12px/16px/12px 越界=0 纵裁=0 末字留白=14
>   div > div.ws-stage.plate > div.ws-scroll pad=16px/16px/16px/16px 越界=0 纵裁=0 末字留白=16
> ```
>
> **`inkGap` 的判读**：拿它跟该容器自己的 `padding` 比，别跟 0 比。上面 `.hero` 的 `padding-right` 是 0
> 而 `inkGap=12`，说明标题末行离边框还有 12px，没问题；白卡容器（`.ws-scroll`）的 `padding` 是 16、
> `inkGap` 也是 16，说明卡内文字正好顶到 padding 内沿 —— 这才是「padding 生效了」的正确形态。
> `inkGap` 明显小于 `padding` 或等于 0 才是问题。

## 三、三个实证案例（方法的有效性证据）

### 案例 1：`.ledger em` —— 一条长 token 把整页撑宽 40px

用户只说「首页右侧卡片跑到视口外面去了」。但 8 档宽度扫下来，卡片右缘距视口**一直有 45.6~133.8px**，
≥1200px 根本没有横向溢出。真正存在的是 ≤1100px 的横向滚动条，而它的元凶完全不在评论区，在统计条：

逐级追链（`scrollWidth > clientWidth` 口径）：

```
section.ledger > div > em      +60 ~ 78px
section.ledger > div           +36 ~ 64px
section.ledger                 +41 ~ 64px
#main                          +6  ~ 23px
document                       +3 / 8 / 23 / 40px   （@1100 / 1080 / 1024 / 960）
```

落到叶子上一看：`.ledger em` 的文本是 `newest/oldest/hottest/mostLiked`，**斜杠处不换行**，
`min-content` 恒为 **211px**，而 4 列栅格里这一格只有 117.9~150.8px。栅格用了 `minmax(0, 1fr)`，
格子能缩，但格子的**内容**缩不了，于是内容从格子里溢出去，一路把文档撑宽。

修法一行：`.ledger em { overflow-wrap: anywhere }`。

> **`anywhere` 而不是 `break-word`**：只有 `anywhere` 参与 `min-content` 计算，`break-word` 不参与 ——
> 写 `break-word` 字会换行，但栅格列的 `min-content` 仍是 211px，照样溢出。这个区别是本例的关键。
>
> 复现手法（不改文件）：注入 `.ledger em{overflow-wrap:normal}`（同特异性、后出现即覆盖），量完 `remove()`。
> 实测 1100/1080/1024/960 四档改前 3/8/23/40 → 改后全 0。

### 案例 2：`.ws-check .desc` —— 69px 纵向裁切，只有第 ④ 条断言抓得到

用户说「插件描述还被垂直截断」。这类问题：
- 元素级 `rect` 完全正常（`-webkit-line-clamp` 只裁**内容**，盒子尺寸是规规矩矩的 2 行高）；
- 不产生任何越界、不产生任何横向溢出；
- 只有「`scrollHeight - clientHeight > 1` 且 `overflowY: hidden`」这一条能抓到。

实测：`.desc` 的 `scrollHeight` 是 103.5px（6 行），`clientHeight` 是 34.5px（2 行），**切掉 69px**。
1440 视口下 17 条描述里 **16 条**被切。改法是把 `-webkit-line-clamp: 2` 去掉（`display: -webkit-box`
一并还原成 `block`），改后裁切 0、最长 6 行完整显示。

### 案例 3：「正文末字 0.7px」为什么元素级 rect 量不出来

`CommentCore` 的根节点只内联了 `background/color/fontFamily`，**没有 padding**；时间戳那个 span 用
`margin-left: auto` 顶到最右。于是：

| 测量方式 | 改前结果 | 说明 |
|---|---|---|
| `.vc-content`（元素 `rect`）距白卡右缘 | **0px** | 恒等于 padding，本身没毛病，看不出问题 |
| 时间戳 span（**叶子**元素 `rect`）距白卡右缘 | **0px** | 叶子元素 rect 是准的，能看出来 |
| 文本节点 `Range` 墨迹距白卡右缘 | **0.7px** | 真实墨迹，量化到亚像素 |

结论：**叶子元素用 `rect` 可以，块级容器必须用 `Range`**。前者会撑满，后者才是墨迹。
本例最终把 padding 加到组件根节点（`CommentCore.tsx` 的 `padding: 16`），8 张卡全部受益，
改后时间戳留白 16px、末字留白 26.7px。

## 四、踩过的三个坑（假阴性 / 假阳性）

这三个都会让你得出**与事实相反**的结论，而且不报错。

### 坑 1：只改 hash 不触发 `load` → `await` 永不 resolve

```js
// ✗ 卡死：同文档导航，load 不会再触发
fr.src = "/vane-comment/#/a"; await onload(fr);
fr.src = "/vane-comment/#/b"; await onload(fr);   // ← 永远卡在这里
```

现象：「跑完第一档就再无输出」，页面看起来正常、控制台无报错。极易误判为 **iframe 挂死**（换标签页无效，
因为不是挂死）。真凶是 `HashRouter` 的 hash 变化属于同文档导航。
**修**：每次先 `src="about:blank"` 并 `await onload`，再设真实 URL 并再 `await` 一次（见 2.2）。

### 坑 2：不等 `document.fonts.ready` → 溢出量被量成 0

demo 全站 webfont（JetBrains Mono / Chakra Petch）。字体未就绪时回退字体更窄，
`.ledger em` 的 `min-content` 可能小于格子宽度 → **溢出为 0**，得出「没问题」。
这解释了为什么 CDP 三档扫不到 `.ledger em` 那条（另一个原因是路由没覆盖 `#/`，`.ledger` 只在首页）。
**修**：`await win.document.fonts.ready` 之后再等 350ms（见 2.3）。

### 坑 3：元素级 `getBoundingClientRect()` 做减法恒等于 padding

block 元素的 `rect.right` ≈ 容器 content-box 右缘，所以

```
容器右缘 − 块级子元素右缘 ≡ 容器的 padding-right
```

你测的是 padding，不是内容位置。padding 为 0 时得 0、改成 16 时得 16，两次都「看起来合理」，
于是漏掉「末字只差 0.7px」这种真正贴死的状态。
**修**：`Range.getClientRects()` 取文本节点墨迹（见 2.5）。

## 五、可直接复用的最小骨架

放 `demos/` 下任意文件名（例：`demos/_geometry.html`），用
`node scripts/serve-demo.cjs demos 3350` 起服务后访问：

```
http://127.0.0.1:3350/_geometry.html?pkg=vane-comment&routes=/,/plugins&w=1440,1080,960&mark=.vc-comment&sel=.hero,.ws-panel,.ws-scroll
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `pkg` | 包名（拼成 `/<pkg>/#<route>`） | `vane-comment` |
| `routes` | 逗号分隔的 hash 路由 | `/` |
| `w` | 逗号分隔的视口宽度 | `1440,1080,960` |
| `mark` | 等这个选择器出现才算挂载完成 | `body` |
| `sel` | 重点体检的容器选择器（逗号分隔，可省略＝只量文档级溢出） | 空 |

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <title>geometry audit</title>

  </head>
  <body>

    <script type="module">
      const q = new URLSearchParams(location.search);
      const PKG = q.get("pkg") ?? "vane-comment";
      const ROUTES = (q.get("routes") ?? "/").split(",").filter(Boolean);
      const WIDTHS = (q.get("w") ?? "1440,1080,960").split(",").map(Number);
      const MARK = q.get("mark") ?? "body";
      const SELS = (q.get("sel") ?? "").split(",").filter(Boolean);

      const fr = document.getElementById("fr");
      const out = document.getElementById("out");
      const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
      const R1 = (v) => Math.round(v * 10) / 10;
      const px = (v) => parseFloat(v) || 0;

      /** 好读的定位串：tag.class#id，最多三级 */
      function path(el) {
        const parts = [];
        for (let n = el, i = 0; n && n.nodeType === 1 && i < 3; n = n.parentElement, i++) {
          let s = n.tagName.toLowerCase();
          if (n.id) s += "#" + n.id;
          const c = (n.className || "").toString().trim().split(/\s+/).filter(Boolean).slice(0, 2);
          if (c.length) s += "." + c.join(".");
          parts.unshift(s);
        }
        return parts.join(" > ");
      }

      /** 坑 1：先 about:blank 强制整页重载；坑 2：挂载 → 字体 → 动画 */
      async function open(url, mark) {
        fr.src = "about:blank";
        await new Promise((r) => (fr.onload = r));
        fr.src = url;
        await new Promise((r) => (fr.onload = r));
        const w = fr.contentWindow;
        for (let i = 0; i < 60 && !w.document.querySelector(mark); i++) await sleep(50);
        await w.document.fonts.ready.catch(() => {});
        await sleep(350);
        return w;
      }

      /** content-box 边界：越界/贴边判据的分母 */
      function contentBox(el, w) {
        const r = el.getBoundingClientRect();
        const cs = w.getComputedStyle(el);
        return {
          cs,
          right: r.right - px(cs.borderRightWidth) - px(cs.paddingRight),
          left: r.left + px(cs.borderLeftWidth) + px(cs.paddingLeft),
        };
      }

      /** 坑 3：文本墨迹必须用 Range，叶子元素才可以用 rect */
      function textInkRight(el, w) {
        let max = -1e9;
        const tw = w.document.createTreeWalker(el, w.NodeFilter.SHOW_TEXT);
        let n;
        while ((n = tw.nextNode())) {
          if (!n.textContent.trim()) continue;
          const rg = w.document.createRange();
          rg.selectNodeContents(n);
          for (const r of rg.getClientRects()) if (r.width) max = Math.max(max, r.right);
        }
        return max;
      }

      /** 四类断言 */
      function auditContainer(el, w) {
        const B = contentBox(el, w);
        const res = {
          sel: path(el),
          pad: [B.cs.paddingTop, B.cs.paddingRight, B.cs.paddingBottom, B.cs.paddingLeft].join("/"),
          scrollX: el.scrollWidth - el.clientWidth,
          escape: [], hug: [], clipY: [],
        };
        for (const k of el.querySelectorAll("*")) {
          const cs = w.getComputedStyle(k);
          if (cs.display === "none" || cs.visibility === "hidden") continue;
          const r = k.getBoundingClientRect();
          if (!r.width && !r.height) continue;
          if (r.right - B.right > 0.5) res.escape.push({ sel: path(k), over: R1(r.right - B.right) });
          else if (B.right - r.right < 4) res.hug.push({ sel: path(k), gap: R1(B.right - r.right) });
          if (k.scrollHeight - k.clientHeight > 1 && cs.overflowY === "hidden")
            res.clipY.push({ sel: path(k), cut: k.scrollHeight - k.clientHeight });
        }
        res.escape.sort((a, b) => b.over - a.over);
        res.clipY.sort((a, b) => b.cut - a.cut);
        res.escape = res.escape.slice(0, 6);
        res.hug = res.hug.slice(0, 4);
        res.clipY = res.clipY.slice(0, 4);
        res.maxEscape = res.escape.length ? res.escape[0].over : 0;
        res.maxClipY = res.clipY.length ? res.clipY[0].cut : 0;
        const ink = textInkRight(el, w);
        res.inkGap = ink > -1e9 ? R1(B.right - ink) : null;
        return res;
      }

      /** 溢出溯源：跳过 fixed 装饰与故意横向滚动的代码块 */
      function overflowChain(w) {
        const de = w.document.documentElement;
        const hits = [];
        for (const el of w.document.body.querySelectorAll("*")) {
          const cs = w.getComputedStyle(el);
          if (cs.display === "none" || cs.position === "fixed") continue;
          if (el.closest(".code, .guides")) continue;
          if (el.scrollWidth - el.clientWidth > 0)
            hits.push({ sel: path(el), over: el.scrollWidth - el.clientWidth, ox: cs.overflowX });
        }
        return {
          inner: w.innerWidth,
          client: de.clientWidth,
          docOvf: de.scrollWidth - de.clientWidth,
          chain: hits.slice(0, 8),
        };
      }

      const lines = [];
      const report = [];
      for (const width of WIDTHS) {
        fr.style.width = width + 15 + "px";
        fr.style.height = "900px";
        for (const route of ROUTES) {
          const w = await open(`/${PKG}/#${route}`, MARK);
          const vp = overflowChain(w);
          const run = { width, route, viewport: vp, containers: [] };
          for (const s of SELS) {
            const el = w.document.querySelector(s);
            if (el) run.containers.push(auditContainer(el, w));
          }
          report.push(run);

          lines.push(`\n== ${width}px ${route} | inner=${vp.inner} client=${vp.client} | 文档横向溢出=${vp.docOvf}`);
          for (const c of vp.chain) lines.push(`   链 ${c.sel} +${c.over} overflowX=${c.ox}`);
          for (const c of run.containers) {
            lines.push(`  ${c.sel} pad=${c.pad} scrollX=${c.scrollX} 越界max=${c.maxEscape} 纵裁max=${c.maxClipY} 末字留白=${c.inkGap}`);
            for (const e of c.escape) lines.push(`      越界 +${e.over} ${e.sel}`);
            for (const e of c.clipY) lines.push(`      纵裁 ${e.cut}px ${e.sel}`);
          }
          out.textContent = lines.join("\n");
        }
      }

      // 回传并把状态写进 title：回传失败时能一眼看出来，不用去猜 JSON 为什么没更新
      let post = "?";
      try {
        const res = await fetch("/_audit-report", {
          method: "POST",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({ pkg: "geometry", runs: report }),
        });
        post = "ok" + res.status;
      } catch (e) {
        post = "ERR:" + e.name;
      }
      const ovf = Math.max(0, ...report.map((r) => r.viewport.docOvf));
      const esc = Math.max(0, ...report.flatMap((r) => r.containers.map((c) => c.maxEscape)));
      document.title = `geo ${PKG} | runs=${report.length} | maxDocOvf=${ovf} | maxEscape=${R1(esc)} | post=${post}`;
      out.textContent += `\n\n-- done (post=${post}) --`;
    </script>
  </body>
</html>
```

## 六、验收口径

判断「几何体检过了」，要同时满足：

| 检查 | 通过线 | 命令/证据 |
|---|---|---|
| 文档横向溢出 | 所有被测宽度 = 0 | `viewport.docOvf` |
| 子元素越界 | 所有容器 `maxEscape` = 0 | `containers[].maxEscape` |
| 纵向裁切 | 目标文本 `maxClipY` = 0 | `containers[].maxClipY` |
| 贴边 | 目标容器内无 `gap < 4px` 的项 | `containers[].hug` |
| 末字留白 | 与容器 padding 一致（不是 0） | `containers[].inkGap` |
| 回归 | 改动前后各量一轮，两列数字都留档 | 回报里给「改前 → 改后」对照表 |

配套门禁（与对比度体检相同）：

