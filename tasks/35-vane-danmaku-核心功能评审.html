01

核心数据流与职责边界

弹幕文本从不进入 DOM，全部经 canvas 绘制；插件只在数据面做变换，DOM 插槽只承载交互控件。这条约束是安全性成立的基础，也是后面多数问题的定位坐标。

① 原始数据

消费方传入 items（id / text / mode / time / duration / meta）。

② transformData 链

24 个数据面插件按优先级顺序过滤 / 打码 / 富化 / 写 renderHint。

③ 调度器 tick

按 currentTime 激活、选轨（干净轨 → 最少遮挡轨）、推进、回收、算 alpha。

④ canvas 绘制

DPR 变换 → evenodd 裁剪避让区 → 描边文字 / 底块 / 角标。

⑤ DOM 插槽

renderHeader / renderOverlay / renderFooter 只放 React 控件。

02

已验证成立的核心机制

这几条是弹幕组件最容易写错、也最容易被误判为 bug 的地方。逐条按代码与测试核对后，结论是「成立」，不应作为问题上报。

✓防追尾判定是解析正确的

速度按 (W + width) / duration，长弹幕更快。代码条件是 sNew * edge > sOld * W → 拒绝，与解析解 τ碰撞 >= τ离场 推导结果完全等价，不存在「差一点点仍追尾」的漏洞。

✓初始 x 必须是入场位

同帧多条目到达时，若初值 x=0，trackFree 会误判同轨空闲造成叠字。现按方向初始化为 W / -width，overlap 测试以 0 像素交叠验证通过。

✓时钟回绕不复活

fired 集合保证每条每周期只入场一次；回绕（currentTime < lastTime - 0.5）时整体清空重置，回归测试覆盖。

✓饱和时丢弃而非叠字

无空轨先入 waiting 吸收 1 秒突发，超过 WAIT_MAX = 1.2s 计数丢弃；每帧最多 48 次选轨尝试，避免碰撞判定打爆主线程。

✓避让区「人物身上零像素」

调度用遮挡权重（而非布尔）避免全屏人物导致所有轨道不可用，最终由绘制期 evenodd 裁剪兜底；调度阶段不做瞬移挪轨，避免跳帧与碰撞假设失效。

✓宽度测量与绘制一致

核心把真实 ctx.measureText 作为 measureWidth 注入调度项，避免字符类估算在 emoji / 粉丝牌 / 长拉丁串上偏小导致速度漂移。

✓fadeMs 单位修复到位

渐隐按 fadeMs / 1000 换算为秒再与 elapsed 比较，历史上「毫秒当秒用导致近乎全透明」的缺陷已修复。

✓DPR 与离屏裁剪

canvas 后备尺寸按 DPR（上限 2）放大、绘制用 CSS 像素坐标；完全出画或 alpha≈0 的条目跳绘制，省掉最贵的光栅化。

03

P1 问题（建议本迭代修）

以下 5 条都会在「真实播放器接入 / 压测 / 运行时改插件配置」场景中被触发，且都有明确代码证据。

P1-1 · 运行时重建插件配置不生效（按 name 缓存导致闭包陈旧）

P1
证据 1
packages/vane-plugin-core/src/react/usePluginRuntime.ts:97-105
const namesKey = plugins.map((p) => p.name).join("|");
useLayoutEffect(() => {
  manager.clear();
  manager.registerAll(plugins);   // 仅在 name 集合变化时重跑
}, [namesKey]);
证据 2
同文件 :119-123，orderedPlugins 的 useMemo 同样只依赖 namesKey，而 transformData 依赖 orderedPlugins。
后果
消费方用 createXxxPlugin({ words: [...] / enabled: false }) 重建同名插件时，注册与数据链仍持有旧闭包：FilterTogglePlugin 文档承诺的「按 key 重建数据面插件」实际无效，过滤开关点了没反应；改敏感词列表同样不生效。
建议
把依赖升级为插件引用集合（如 plugins 数组本身或 name+config 版本号），或在 HOC 内对 plugins 做稳定化后重注册；同时给 enabled 变化补一条回归测试。

P1-2 · 暂停时弹幕全部回到入场位，恢复时瞬移

P1
证据
packages/vane-danmaku/src/components/DanmakuPlugin/render.ts:459
// compute()
const elapsed = playing ? currentTime - a.enterAt : 0;   // 暂停 → elapsed 归零
if (a.mode === "scroll") {
  const x = size.width - speed * elapsed;               // 全部回到右缘
  return { x, y, done: x + a.width < 0 };
}
叠加
render.ts:274-283 中 if (playing) 才计算 fade，暂停时 alpha 被强制为 1，刚入场未渐显的条目会瞬间全亮。
后果
与 DanmakuCoreProps.playing 注释「暂停时弹幕静止（仍绘制当前帧）」相反：一按暂停，所有在飞弹幕塌回右边缘重叠成一条；继续播放时 elapsed 含暂停时长，直接跳到更远处，视觉上像瞬移。
建议
记录 pausedAt，用「有效播放时间」推进：elapsed = (pause 时取 currentTime - pausedAt) + ...，或维护一份不受暂停影响的 clockOffset；暂停时不重算 alpha。补一条「暂停 2s 前后 x 不变」的单测。

P1-3 · 数据流水线每次渲染全量重跑，副作用按渲染次数重复触发

P1
证据 1
src/components/DanmakuPlugin/withPlugins.tsx:58-63 —— transformData 在渲染函数体内无条件执行，无 memo、无脏检查。
const baseData = (runtime.context.data as DanmakuData) ?? { items: props.items };
const transformed = (runtime.transformData(baseData) as DanmakuData) ?? baseData;
证据 2
src/custom-plugins/CmdParsePlugin/create.tsx:57 每次 transformData 都 bus.emit("danmaku:command")；AuditLogPlugin/create.tsx:38-41 每条都 onLog / emit("danmaku:audit")。
后果
父组件每推进一次 currentTime（播放器 timeupdate 约 4Hz）就会重跑整条链：/clear 指令被重复广播、抽奖回调被重复触发、审计写入重复（数据正确性问题）；同时成本为 O(插件数 × 弹幕数)/渲染，3000 条 × 24 插件 × 4Hz ≈ 30 万次操作/秒。
建议
以 props.items 引用 + 插件集合为依赖做 useMemo；把「指令 / 审计」这类副作用从 transformData 挪到带去重集合的独立钩子（或按 item.id 记已处理）；补测试：同一份 items 连续渲染 N 次只应 emit 一次。

P1-4 · 数据面插件异常没有隔离，一个抛错会打断整棵渲染

P1
证据
packages/vane-plugin-core/src/react/usePluginRuntime.ts:162-174：transformData 顺序调用插件钩子，无 try/catch；plugins/slots.tsx:62 的 PluginErrorBoundary 只保护 DOM 插槽。
for (const plugin of orderedPlugins) {
  const fn = plugin.hooks?.transformData;
  if (typeof fn === "function") next = fn(contextRef.current!, next);  // 抛错直出
}
后果
任一插件对脏数据抛错（如 text 为 undefined、配置正则非法、第三方插件 bug）会让 HOC 渲染阶段直接 throw，整个弹幕组件白屏，且错误边界也接不住（发生在 Core 之上的 render 期）。内核文档宣称的「钩子沙箱执行」在这一条路径上并未生效。
建议
在 transformData / transformProps 循环内逐插件 try/catch，失败时跳过该插件并 logger.warn（可复用一个 safeRunPlugin）；补「插件抛错时其余插件仍生效」测试。

P1-5 · rAF 帧内异常会让渲染循环永久停摆

P1
证据
src/components/DanmakuPlugin/DanmakuCore.tsx:171-224：raf = requestAnimationFrame(frame) 写在 frame 末尾，tick / clipZones / draw 均无 try/catch。
for (const a of active) {
  if (a.x > width || ...) continue;
  draw(a, ctx, opts);          // 一旦 throw，后续 schedule 不会执行
}
...
raf = requestAnimationFrame(frame);   // 这行被跳过 = 循环死亡
触发面
ctx.roundRect 在旧版 Safari / 部分 Android WebView 缺失；插件可写入任意 meta.fontFamily / renderHint.highlight，异常字体字符串或 Canvas 扩展缺失都可能抛错。异常只出现在某一帧时，弹幕整体冻结且无任何报错提示，很难定位。
建议
把 requestAnimationFrame 调度移到 frame 开头（或 try/finally 中），帧内绘制异常只跳过该帧并计数；对 roundRect 做一次能力检测，缺失时退回 rect。
04

P2 问题（可排期，不影响主链路）

这些多为 API 契约、成本与可维护性问题；单独看不致命，但组合起来会拉高接入成本与排障难度。

P2-1 · 每帧对全量 items 线性扫描，未利用 time 有序性

P2
证据
render.ts:208-219：for (const item of items) + fired.has(id)，已入场的条目每帧仍要判一次；item.time > currentTime 用的是 continue 而不是 break。
后果
3000 条压测场景下，稳态每帧约 3000 次 Set 查询 + 全部条目遍历（60fps ≈ 18 万次/秒），与真实在飞条数（通常几十条）完全不成比例。
建议
维护「已消费游标」（基于 time 升序），并把 continue 改 break（需在文档明确 items 按 time 升序；否则先用 Set 记录 pending 索引）。

P2-2 · 三个 UI 插件声明的配置项从未被使用

P2
证据
CommandInputConfig.placeholder（:10-11）声明后，输入框仍硬编码 "发条弹幕 / 指令（/clear）"（:66）；FilterToggleConfig.defaults（:10-11）被忽略，状态一律初始化全开（:49-51）；SettingsPanelConfig.opacity/speed/trackHeight（:10-16）初始值被忽略，状态硬编码 1 / 1 / 28（:44-46）。
后果
TS 类型承诺了可配置，运行时静默失效——接入方按文档传参不生效，属于「文档 / 类型与实现不一致」。
建议
要么读取配置并初始化状态，要么删除这些字段，避免假契约。

P2-3 · KeywordHighlight 每条每渲染都新建正则

P2
证据
KeywordHighlightPlugin/create.tsx:28：new RegExp(...) 写在 buildRich 内，而 buildRich 对每条弹幕调用；对比 AtMentionPlugin 在工厂函数外只建一次。
后果
N 条 × 每次渲染一次正则编译，叠加 P1-3 的全量重跑，是流水线里最贵的一处；关键词多时 alternation 也会放大匹配成本。
建议
把 RegExp 提到 createKeywordHighlightPlugin 闭包内只建一次（并用 lastIndex = 0 或 matchAll 规避 g 状态）。

P2-4 · 可配置面缺失：fadeMs / gap / defaultDuration / accent 写死

P2
证据
DanmakuCore.tsx:17-28 的 DEFAULTS 中 fadeMs:450 / gap:24 / defaultDuration:8 与 accent / stroke 均为常量，而 DanmakuCoreProps（types.ts:111-140）没有对应字段。
后果
消费方无法调节渐隐时长、同轨间距与默认飞行时长；想改主题色也只能改 renderHint，与「内核只做绘制、业务交插件」的定位不太一致。
建议
把这几项提升为可选 props（带默认值），或在 transformProps 中开放白名单。

P2-5 · 渲染期副作用：每渲染 new Scheduler、liveRef 直接赋值

P2
证据
DanmakuCore.tsx:92 useRef(new DanmakuScheduler())——参数在每次渲染都会构造一个新实例（随后被丢弃）；:109-119 在渲染函数体内给 liveRef.current 整体赋值。
后果
前者是纯 GC 浪费；后者在并发渲染（未来 React 19 特性）下属于「渲染期写 ref」，可能拿到未提交的中间值。当前 React 18 下不报错。
建议
改为 const ref = useRef<DanmakuScheduler>(); if (!ref.current) ref.current = new DanmakuScheduler();；liveRef 更新挪到 useLayoutEffect。

P2-6 · 避让区覆盖率重复累加，可能误放弃裁剪

P2
证据
DanmakuCore.tsx:35-51：covered += w * h 直接相加，未做重叠去重；超过 85% 即返回 null（完全不裁剪）。
后果
两个相互重叠的避让框（人物 + 安全区条带）就能达到 2 倍面积，误判为「几乎覆盖全屏」而放弃裁剪，与「人物区域绝不能有弹幕」的最终保证冲突。
建议
按行扫描或先合并矩形再算面积；或把阈值判断改成「有效可用轨数 > 0」。

P2-7 · 清屏能力未闭环，clear() 为死代码

P2
证据
render.ts:442-445 定义了 clear()，但 DanmakuCoreRef（types.ts:142-154）未暴露；全包仅此一处定义，无调用点。且 clear() 不清 fired / lastTime / dropped。另 getStats().dropped 文档称「本周期」，但只在时钟回绕时归零。
后果
CmdParse 广播了 clear 事件，但组件没有对应 API，消费方只能清空 items，语义与「清屏但保留时间轴」不符；读数含义也不精确。
建议
在 ref 上暴露 clearScreen()（清 active + waiting，保留 fired 以免复活），并把 dropped 改为可重置周期计数。

P2-8 · 插槽 key 带 index，插件顺序变化会丢面板状态

P2
证据
plugins/slots.tsx:62 key={`danmaku-slot-${plugin.name}-${index}`}；useDanmakuSlot 在 Core 渲染体内直接调用插件 hook（:44-72）。
后果
插件顺序变化 → index 变 → React 视为新节点重挂载，SettingsPanel 的展开态 / FilterToggle 的开关态被重置。当前插件都返回组件，所以 hooks 规则没被破坏；但契约上「hook 内不得调用 React hooks」未写明，新插件很容易踩雷。
建议
key 只用 plugin.name；在类型注释中明确「这些槽位函数必须是纯渲染函数，不得调用 hooks」。

P2-9 · 无障碍与生命周期边界

P2
证据
FilterTogglePlugin:65 用 <span onClick> 作开关，无 role / tabIndex / 键盘事件；CommandInputPlugin:63 输入框无 aria-label；canvas 无 aria-label / 替代文本；DanmakuCore.tsx:171 没有 document.hidden 或 IntersectionObserver 门控（后台/离屏仍跑 rAF）。
后果
键盘用户无法切换过滤项；屏幕阅读器拿不到弹幕语义（canvas 本身不可读，需要 DOM 摘要或 aria 说明）。后台页 rAF 会被浏览器节流，影响有限但会白跑。
建议
chip 改 <button aria-pressed>；canvas 加 role="img" + aria-label；渲染循环加 visibility 门控。
05

安全审查（security-best-practices）

结论：没有可利用的注入面。原因是渲染分两条隔离的路径——文本走 canvas，控件走 React JSX；不存在字符串拼接 HTML 或 DOM API 写入。

注入与凭证

XSS安全弹幕正文经 ctx.fillText / strokeText；全包无 innerHTML / dangerouslySetInnerHTML / new Function / eval（仅 highlight.ts 注释提到「不走 innerHTML」）。
DOM 槽位安全插件返回 ReactNode，字符串由 React 自动转义；PluginErrorBoundary 还兜住了插槽渲染异常。
外部资源安全无远程脚本 / 图片加载，EmojiRenderPlugin 只做短码 → unicode 替换，不产出 URL，因此不存在 javascript: 伪协议面。
凭证已清早前仓库级评审的 P0（.npmrc 明文 npm 令牌）在当前 .npmrc 中已检索不到 _authToken。
发布面注意package.json 仅发布 dist，demo/ 与测试不进包；但 exports 同时暴露 ./custom-plugins/* 与具体插件路径，两套入口需长期保持一致。

拒绝服务面（开发者可控配置）

ReDoS低危SensitiveFilter / KeywordHighlight / EmojiRender 用 new RegExp 拼装关键词。关键词来自配置而非用户输入，但若把后台下发的词库直接灌进来，嵌套量词会造成单条弹幕匹配退化 → 掉帧。
配置注入低危EmojiRender 把 config.map 的 key 直接拼进正则未转义，含正则元字符的 key 会在 create 阶段抛错；GiftCombo 的 pattern 同理。
绘制参数安全meta.color 等任意字符串只进 ctx.fillStyle，非法值被 Canvas 忽略，不构成注入；但配合 P1-5 的异常路径需注意兜底。
建议对 EmojiRender 的 key 用 escapeRegExp；词库限制长度并做超时熔断；为 transformData（P1-4）加隔离。
06

React / 性能审查（vercel-react-best-practices）

按「避免无谓渲染 / 避免热路径分配 / 保证 effect 生命周期正确」三条主线核对。

成立的部分

rAF 生命周期正确effect 依赖稳定的 containerRef，卸载 cancelAnimationFrame；渲染循环通过 liveRef 读最新 props，不需要重建循环。
热路径正确宽度只量一次（measured 标记）、离屏与近透明条目跳过绘制、每帧最多 48 次选轨尝试，均是有针对性的成本控制。
StrictMode可用插件注册在 useLayoutEffect，双执行只会重复注册同一批插件，不产生重复渲染实例。

缺口

重渲染DanmakuSlotProvider 的 useMemo 依赖 context，而 context 每次渲染都是新对象 → memo 完全失效，插槽每次都重新求值（P1-3 的放大器）。
渲染期计算HOC 在 render 阶段跑整条插件链（副作用 + O(P×N)）；transformProps 结果的重要字段又被原始 props 覆盖（trackHeight / opacity 等，见 withPlugins.tsx:82-96），插件想改这些不生效。
布局抖动ResizeObserver 回调里先 getBoundingClientRect() 再写 canvas 尺寸，未使用 entry.contentRect，存在一次额外 reflow 的风险。
内存fired / waiting 以 id 为键无上限增长；长直播（唯一 id 持续增长）需消费方定期换 items 或组件重建。
