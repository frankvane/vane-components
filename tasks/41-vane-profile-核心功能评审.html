01

核心数据流与职责边界

整包只有一条数据流：消费方的 props 进上下文，插件按槽位产出 JSX，Core 负责排版。没有任何一环做「数据合并 / 校验 / 拉取」。这也解释了为什么任务清单里的大部分检查项在代码里找不到实现——不是写得不好，而是根本没有。

① 消费方 props

stats / followState / verified / banner / data? 由宿主管；data 是 T 泛型原样透传，无 schema。

② extendContext

在 usePluginRuntime 的 context 上叠 activeTab（读内核 state）、setActiveTab 与 props 字段。

③ 领域槽渲染

ProfileCore 对 7 个槽各调一次 renderProfileSlot：过滤 → 排序 → 逐个调插件函数。

④ 插件产出

16 个插件只做「读 ctx + 返回 JSX」，唯一有内部态的是 FollowEcho / QRShare。

⑤ 回写

交互只回调 onFollow / onStatClick / onChange；真相由消费方改 props 后重渲染，包内无乐观层、无 pending、无 error。

02

已验证成立的核心机制

下面几条是逐条对照代码与单测后确认「确实成立」的，不应作为问题上报；它们也说明这个包的真实能力边界是「可组合的主页排版」，而不是「资料引擎」。

✓单插件抛错不连坐

renderProfileSlot 对每个插件先 try/catch 包住 hook 调用（slots.tsx:69-76），再套一层 PluginErrorBoundary；测试 core-render.test.tsx:75-89 用 throw new Error("boom") 验证：banner 空掉，但 StatRow 仍渲染。

✓页签联动是真链路

TabSync 点按 → context.setActiveTab → 内核 state 变化 → context 重建 → onTabChange 触发（withPlugins.tsx:113-122）；plugins.test.tsx:32-51 断言内容区文本从 none 变 feeds。

✓FollowEcho 的受控重置有效

按钮以 key={state} 挂载（FollowEchoPlugin:96-107），props 的 followState 一变就整颗重挂载拿新初值，不存在 stale 内部态；onPropsChange 只在非 mutual→mutual 时触发 onMutual（测试 :79-89）。

✓同名插件换配置可生效

内核按插件对象引用判断是否重注册（plugin-core/src/react/usePluginRuntime.ts:100-117），不再只比 name；上一轮 vane-danmaku 的「同名换配置不生效」在此包已不存在。

✓空数据不占位

BioSlot / TagList / SocialLinks / ContactCard / ActivitySummary / StatRow 在空集合时统一返回 null（如 BioSlotPlugin:41、StatRowPlugin:41），不会输出空容器或「undefined」字样。

✓槽内排序确定且可预期

config.order 升序 → priority 降序（slots.tsx:64-68），与内核 composeSlots 同一规则；BioSlot(12)、SocialLinks(12)、TagList(12) 同区串联的顺序稳定。

✓根容器配色成对

Core 根节点同时写 background:"#fff" 与 color:"#1f2328"（ProfileCore.tsx:79-80），深色宿主里不会出现「#080a09 上的 #555」；这与 ADR-13 一致。

✓外部资源全部内联

徽标/图标为内联 SVG 或单字占位（VerifyBadgePlugin:21-36、PRESET），无远程字体/图片依赖；二维码为本地点阵占位（QRSharePlugin:18-31），不引第三方库。

03

P1 问题（建议本迭代修）

这 5 条都会在「真实接入主页」时被触发：要么状态没人能改，要么失败后 UI 说假话，要么关键内容被吞掉。

P1-1 · 关注按钮的乐观态没有回滚通道，失败后永久停在「已关注」

P1
证据 1
packages/vane-profile/src/custom-plugins/FollowEchoPlugin/create.tsx:46-52
const [state, setState] = useState<FollowState>(initial);
const handle = () => {
  const next = state === "none" || state === "mutual" ? "following" : "none";
  setState(next);       // 先改 UI
  onToggle(next);       // 回调是 (next) => void，拿不到 Promise
};
证据 2
同文件 :96-107 用 key={state} 让按钮「随 props 重挂载」；:33 注释写「mutual 视为只读」，但 :49 允许 mutual → following（互相矛盾的契约）。
后果
关注请求失败时，消费方通常把 followState 回写成原值（"none"）——值没变，key 没变，不会重挂载，按钮就停在「已关注」。用户以为自己关注了、实际服务端没有；只有等下一次 props 真的变化或组件重挂载才恢复。同样的窗口内连续点击会重复发请求（无 in-flight 锁）。
建议
把 onFollow 改为 (next) => void | Promise<void | {error}>；内部维护 pending（禁用/loading）与 failed（回退到 initial）；或在 props 增加 followStateVersion 让同值也能触发重置。补一条「onFollow reject 后按钮回到原态」的单测。

P1-2 · 页签状态不可受控，也没有外部设置入口

P1
证据 1
packages/vane-profile/src/components/ProfilePlugin/plugins/types.ts:49-50：props 只有 defaultActiveTab?: string | null，没有 activeTab、没有 onActiveTabChange。
// withPlugins.tsx:56-59
activeTab: (base.state?.activeTab ?? props.defaultActiveTab ?? null),
setActiveTab: (id) => base.setState({ activeTab: id }),
证据 2
types.ts:83-84 的 ref 只有 getActiveTab()（只读），整包没有对外暴露 setActiveTab 的入口。
后果
URL 深链（/?tab=works）、刷新后恢复页签、以及「切换到另一个用户后重置页签」三件事都做不到：宿主既读不到变化事件，也改不了状态。defaultActiveTab 在用户点过一次之后失效（state.activeTab 一旦有值就永远优先）。
建议
加 activeTab?: string | null（受控）与 onActiveTabChange?: (id, prev) => void；受控时 TabSync 只调回调、不写 state。补一条「受控模式下点页签不改内部态」的单测。

P1-3 · 启用内容插件后，内核 header / overlay / footer 插件被整体吞掉

P1
证据 1
packages/vane-profile/src/components/ProfilePlugin/withPlugins.tsx:138-146：HOC 把 composeSlots(orderedPlugins, context, children) 塞进 enhancedProps.children——内核三槽（含 renderHeader/renderOverlay/renderFooter）都在这个 children 里。
证据 2
ProfileCore.tsx:148-152
<div className="vp-content-area" style={{ padding: "16px" }}>
  {contentSlot.length > 0 ? contentSlot : children}
</div>
后果
只要装上 WorksGrid 或 AchievementWall（且当前页签命中，contentSlot.length > 0），整个 children 被丢弃，于是：宿主自己的内容、以及所有走内核 renderHeader / renderOverlay / renderFooter 的插件（例如悬浮提示、页脚）全部消失。表现是「加了作品网格，别的自定义块突然没了」，非常难定位。
建议
把内核三槽产物在 HOC 里改成独立 prop（如 kernelSlots）并在 Core 中固定渲染；内容区只用 {contentSlot}{children}（或显式 children 优先 的可选开关）。

P1-4 · 外部链接与头图 URL 全部直出，无协议白名单

P1
证据 1
src/custom-plugins/SocialLinksPlugin/create.tsx:77-82
<a key={i} className="vp-social-item" href={link.href}
   target="_blank" rel="noreferrer noopener">…</a>
证据 2
ContactCardPlugin/create.tsx:41-47 直接把 site 当 href（仅展示时 replace(/^https?:\/\//) 去掉协议），:82-88 原样输出；BannerSlotPlugin/create.tsx:45-47 把 cover 拼进 CSS：`url(${cover}) center/cover no-repeat`。
后果
主页资料里的社交链接/官网/头图是用户可编辑内容。当前没有任何协议校验：可写入 javascript:（React 会拦截但对 vbscript: / 自定义 scheme 无力）、data:、任意外站钓鱼页；cover 直接插入 CSS url() 且未加引号，一个含 ) 的字符串即可破坏整段样式或注入额外声明。属于「可被用户内容驱动的输出面」，而不是纯展示。
建议
统一一个 safeHref(url)：new URL() 解析后仅放行 http/https/mailto/tel，其余返回 undefined 并降级为纯文本；cover 用 url("${encodeURI(url)}") 并校验 scheme（或改用 <img> + object-fit）。

P1-5 · TabSync 工厂在空 tabs 时直接 throw，异步页签数据会崩整棵树

P1
证据
src/custom-plugins/TabSyncPlugin/create.tsx:51-53
if (!tabs || tabs.length === 0) {
  throw new Error("[vane-profile] TabSync 至少需要一个 tab");
}
后果
页签通常来自异步接口（data.tabs）。消费方若在渲染期构造插件数组（withPlugins(Core, [createTabSyncPlugin({ tabs: data?.tabs ?? [] })]) 或 useMemo 依赖 tabs），首帧空数组就会在 React 渲染之前抛出，错误边界接不住（它在 HOC 之外、也不是 React 生命周期内的抛错），直接白屏。工厂也没有 enabled 之类的软关闭开关，调用方只能自己先判断数组长度。
建议
空 tabs 返回一个 enabled:false 的空插件（或 renderTabBar 返回 null），把「必须至少一个」交给 TS 类型/开发期断言；至少不要在生产代码里 throw。
04

P2 问题（可排期，不影响主链路）

契约、成本与可访问性三类；单独看不致命，组合起来会显著抬高接入与排障成本。

P2-1 · 领域槽 key 带 index，插件顺序一变就丢内部状态

P2
证据
src/components/ProfilePlugin/plugins/slots.tsx:81：key={`profile-slot-${plugin.name}-${index}`}。
后果
调整任一插件 order/priority、或增删同槽插件导致 index 位移，会让 QRSharePanel 的展开态、FollowButton 的乐观态被整颗重挂载重置——用户点了关注，换个插件顺序就变回「关注」。
建议
key 只用 plugin.name（插件名在同槽内应唯一）。

P2-2 · SlotProvider 的 useMemo 实为无效，宿主每次重渲染都会打穿所有消费者

P2
证据
slots.tsx:42-45 依赖 [orderedPlugins, context]；而 plugin-core/src/react/usePluginRuntime.ts:157 的 context 依赖 props 与 extendContext，后者又是 useCallback(..., [props])（withPlugins.tsx:52-69）。
后果
props 对象身份一换（宿主 setState 即换），context 必换，memo 必然重算 → Provider value 变化 → 所有 useProfileContext 订阅者与 Core 的 7 个槽全部重跑。Vercel 的 rerender-memo / rerender-derived-state 在这条链上没有落地。
建议
extendContext 依赖收敛为具体字段（props.stats, props.followState, ...），或在 HOC 内用 ref 读取最新 props 让 extendContext 恒稳；context 用 useMemo 按「真正参与渲染的字段」拆成两个 provider（结构 / 交互）。

P2-3 · 每次 Core 渲染做 7 次过滤+排序+全量插件调用

P2
证据
slots.tsx:58-79：[...plugins].filter(...).sort(...).map(...)；ProfileCore.tsx:37-43 一次渲染就调 7 遍，useProfileSlot 无缓存。
后果
插件数为 P 时每帧成本 ≈ 7 × O(P log P) + 7 × P 次 JSX 构造。宿主高频重渲染（如滚动驱动 forceUpdate、父级状态更新）时全部重算；renderContentArea 里的 items.map 也每次都重建整棵网格。
建议
在 HOC 里按 orderedPlugins 预计算 7 份「槽位插件列表」并 useMemo；Core 只做 map 不做 sort。

P2-4 · 渲染期写 ref / 渲染期写 ref.current（并发渲染下不安全）

P2
证据
withPlugins.tsx:80-83 ctxRef.current = runtime.context 写在函数体里；ProfileCore.tsx:47-48 activeTabRef.current = ctx?.activeTab ?? null；withPlugins.tsx:122 effect 依赖还引用了 ctxRef.current.activeTab。
后果
React 18 下不报错，但「渲染期写 ref」违反 rerender-use-ref-transient-values 的用法前提（ref 只做瞬态传递，不做提交期语义）；未来开启并发特性时可能读到未提交的中间 state，onTabChange 的旧/新页签可能错位。
建议
用 useLayoutEffect 同步 ctxRef；onTabChange 直接依赖 ctx?.activeTab 的值（渲染期变量），而不是 ref。

P2-5 · 声明的 transformData 钩子在本包永不执行

P2
证据
withPlugins.tsx:92 只调了 runtime.transformProps(props)；全包检索 transformData 仅命中类型注释（plugins/types.ts:115-116）。插件拿到的 ctx.data 是 props.data 原值（withPlugins.tsx:74-77）。
后果
插件作者按 PluginHooks 写 transformData（例如「把后端字段归一化成 StatItem」）会静默失效，且没有告警；数据归一化只能写死在每个插件里。
建议
要么在 HOC 里对 data 跑一次 runtime.transformData 并下发（配 useMemo），要么在类型层把该钩子从领域接口剔除，避免假契约。

P2-6 · 头像没有任何降级：破图留白、无首字母兜底、alt 为空

P2
证据
src/custom-plugins/BannerSlotPlugin/create.tsx:70-86：<img src={avatar} alt="" />，无 onError、无占位/首字母块、无骨架态；:67 marginBottom: avatarSize / 2 无论有没有头像都生效。
后果
头像 404 / 慢加载时是一个 3px 白边的空圆，比没有头像更难看；未设置头像时头图下方固定多出 32px 空白（与「数据行贴着头图」的预期不符）；alt="" 让屏幕阅读器完全跳过身份信息（头像在有名字时通常应给 alt={name} 或至少 role="img"）。
建议
加 onError 切到「首字母色块」并暴露 avatarFallback；marginBottom 仅在 avatar 存在时生效；提供 avatarAlt。

P2-7 · 空数据态仍在渲染固定容器（空白条 / 空按钮）

P2
证据 1
ProfileCore.tsx:122-139 的 .vp-meta-area 无条件渲染并带 padding:12px 16px；:85 的 .vp-banner-area 也无条件渲染。
证据 2
StatRowPlugin:52-56：未传 onStatClick 时仍输出 <button onClick={undefined}>，成为可聚焦但无作用的空按钮；WorksGridPlugin:114-120 的空态用 opacity:0.6 压字。

P2-8 · 可访问性与示例数据一致性

P2
证据 1
TabSyncPlugin:109-131：页签是裸 <button>，无 role="tab" / aria-selected / aria-controls；QRSharePlugin:48-68 的分享按钮无 aria-expanded，浮层无 Esc/外点关闭。
证据 2
QRSharePlugin:106-116 navigator.clipboard?.writeText 失败分支是空函数，且 :112 的 setTimeout 无清理；:145 缺省 url 硬编码为 https://vane.dev/u/frankvane——接入方忘传 url 就会把真实用户指向示例站。

05

安全审查（security-best-practices）

结论：没有危险 DOM 写入点，但有一个「用户内容驱动的 URL 输出面」。全包无 dangerouslySetInnerHTML / innerHTML / eval / new Function，无 localStorage / cookie / fetch、无 token 处理；风险集中在「把外部 URL 直接交给 href 与 CSS url()」这一族。

注入与凭证

XSS安全所有用户数据都进 React 文本节点（自动转义）；检索 0 命中 dangerouslySetInnerHTML / innerHTML / eval / new Function。
URL 输出P14 处直出：SocialLinksPlugin:80、ContactCardPlugin:44/84、BannerSlotPlugin:45（CSS url）、WorksGridPlugin:99（CSS url）。React 仅拦 javascript:，其余 scheme 与 CSS 注入未被约束。
外链属性安全target="_blank" 均带 rel="noreferrer noopener"（SocialLinksPlugin:81-82、ContactCardPlugin:85-87），无 window.opener 劫持面。
凭证 / 隐私安全不读写 storage、不组 token、不发请求；无日志打印用户数据（仅 console.warn 插件名）。
默认值P2QRSharePlugin:145 的默认 url 指向示例站点，属「默认值事故」而非安全漏洞，但会让用户资产外流到非预期域名。

加固建议

协议白名单抽一个 safeHref()：只放行 http/https/mailto/tel，其他一律降级为纯文本（mailto: 还要校验邮箱字符集，防止 ?subject=&body= 注入预置内容）。
CSS 注入cover 不要裸拼 url()：改用 <img src>（走同一白名单）或 url("${encodeURI(url)}")，并校验长度。
图片avatar 同理走白名单；避免 data: 大体积 base64 撑爆首屏。
依赖面包本身零运行时依赖（仅 peer react / vane-plugin-core），无供应链新增风险；发布仅 dist。
06

React / 性能审查（vercel-react-best-practices）

按「避免无谓渲染 / 避免热路径分配 / effect 与 ref 生命周期」三条线核对。这个包没有 effect 泄漏，也没有监听器未清理（唯一定时器在 QRShare，见 P2-8）；主要缺口是 memo 链路无效与渲染期写 ref。

成立的部分

订阅粒度正确内容区通过 useProfileContext 只读 activeTab 等派生值，而不是把整包 props 传下去；页签切换只引起内容区重渲染。
内部态归属正确有状态控件（FollowButton / QRSharePanel）都被拆成独立组件，useState 发生在 React 渲染上下文内，没有「插件函数里调 hook」的规则破坏。
异常隔离正确渲染期 try/catch + 每插件 PluginErrorBoundary 双保险，坏插件只丢自己那一段（测试已验证）。
生命周期正确onMount 依赖 [execute]（manager 稳定，withPlugins.tsx:85-98），不会随每次渲染重复触发；onUnmount 由内核 useLayoutEffect 统一执行。

缺口

memo 失效SlotProvider 的 value 每次渲染都重新计算（P2-2），useProfileContext 的消费者在宿主任意一次 setState 后全部重渲染。
槽位成本7 次 filter/sort/map 无缓存（P2-3）；orderedPlugins 本身已被内核 memo，但「按槽分组」每次都重做。
渲染期写 refctxRef.current / activeTabRef.current 在 render 期赋值（P2-4），且 effect 依赖引用 ref 的当前值（withPlugins.tsx:122），规则上应改为 effect 内同步。
列表 keySocialLinksPlugin:78、TagListPlugin:46、ContactCardPlugin:83/93 用 key={i}；StatRowPlugin:54 用 key={`stat-${i}`} 作为无 id 时的兜底——增删中间项会错配组件状态（当前无内部态，风险低）。
SSR本包无 Date.now() / 随机数，因此 SSR 与客户端输出一致，不存在 hydration mismatch（对比 vane-sign-in 的 Countdown）。
