七个关注点逐条回应

先给结论，再在 02/03 给出证据与修复方向。

关注点结论评审发现
命令式控制示例有问题 确认 · P1-1 05-imperative.tsx 在组件函数体内调用 withModalSheetPlugins()，每次渲染都生成新的组件类型；progress 每 100ms setState → React 卸载重挂整个弹层 → 关闭/重开动画循环、ref 反复置空。同模式还出现在 02/03/04，其中 04 每敲一个字就重挂，输入框必然失焦。

能力对齐 react-modal-sheet 大体对齐 · 有缺口 snapPoints / initialSnap / detent / onSnap / onClose / 命令式 snapTo / backdrop / header 均已具备。缺口：disableDrag、disableContentDrag 没有对外开关（只有 NestedScroll 的隐式锁）、backdrop 模糊、最大高度、外部关闭动画策略。

宽度可配、最大高度可配 宽度 ✓ / 最大高度 ✗ 宽度：width?: number | string 已进入 Core，居中/左右停靠可用。最大高度：全包 src 只有 ResponsivePlugin 的 maxWidth，没有任何 maxHeight 入口；measure() 直接把面板高度写成视口差值。
20+ 插件的示例配套 缺口较大 · P1-7 21 个插件中仅 8 个在 demo 中出现，1 个只在 selftest（FocusTrap），13 个零示例。场景板只做了 2 块，55 文档里承诺的 iOS modal effect、FocusTrap+Announcer、ActionSheet/Confirm、SharePanel/FilterPanel 都没有落地。
核心功能是否存在问题 存在 · 8 项 P1 几何引擎本身没有崩溃级问题，但边界条件（打开中改档、卸载清理、首帧即开、detent 内容测高）会直接造成「高度不对、页面被锁滚、焦点没进弹层」。详见 02。
02

P1 · 真实接入必踩

按「用户可感知后果」排序，不按文件顺序。

P1-1

逐项示例在渲染期重建组件类型，命令式示例与表单示例实际不可用

P1

证据

demo/src/demos/05-imperative.tsx L31–L35：Enhanced 在 Stage 函数体内创建；L42–L45 每 100ms setProgress；L48–L50 ref.snapTo。
04-keyboard-form.tsx L31–L45 同模式；L68–L71 输入框受控 value。
02-detent-content.tsx L31–L35、03-unstyled.tsx L25–L28 同模式。

正确写法参考 00-basic.tsx L38–L50 的 useMemo，以及 vane-profile PluginsPage L69–L74 按勾选集合 useMemo。

后果

  • 05：每次 progress 更新都卸载重挂 → 弹层无限「重开」，命令式演示的连续性完全丢失；interval 永不停。
  • 04：每输入一个字符重挂 → 输入框失焦，表单示例无法正常输入。
  • 02/03：切换内容/交互时弹层闪闭重开，滚动位置与补间状态丢失。

修复方向

工厂调用移到模块顶层，或按「插件配置签名」useMemo 缓存；禁止在渲染体内直接调用 withModalSheetPlugins。同时在 docs/recipes 写一条反例。

P1-2

最大高度（maxHeight）能力完全缺失，PC 场景无法限制弹层高度

P1

证据

plugins/types.ts L27–L70：仅有 width / horizontalAlign，无 maxHeight。
engine.ts L205–L222：panel.style.height = hiddenY - snapYs[0]，高度只由视口与 snapPoints 决定。
全包检索 maxHeight|max-height 命中 0 处；仅 ResponsivePlugin/create.tsx L45 有 maxWidth。

后果

  • PC 宽屏下 snapPoints=[1] 永远铺满视口高度，无法做 560×720 这类浮窗。
  • ResponsivePlugin 的「桌面浮窗」只限宽，不限高，视觉上是「通栏抽屉」而不是对话框。
  • 与用户明确提出的「最大高度应该也可以设置」直接冲突。

修复方向

Core 增加 maxHeight?: number | string；在 resolveSnapPixels / measure 中先算目标高度再夹到 maxHeight，最高档 y = viewportH - clampedH；补纯函数单测与 demo 控件。

P1-3

打开状态下修改 snapPoints / detent 不会重算几何，档位与面板高度保持旧值

P1

证据

ModalSheetCore.tsx L124–L128 只在 isOpen 变化时 engine.open()；L138–L146 只监听 resize。
01-multi-snap.tsx L54–L60、L126–L131：预设档位与宽度在打开状态下可实时切换。

measure() 仅由 open / snapTo / setViewportInset 触发，没有「snapPoints / detent / content 变化」的 effect。

后果

  • demo 01 打开后切预设：SnapDots 数量、当前档、面板高度仍按旧 snapYs，UI 与声明不一致。
  • 业务侧根据筛选结果动态改档位时会「点了没反应」，直到触发 resize 或重开。

修复方向

Core 增加对 snapPoints（序列化签名）、detent、内容变化的 useEffect：调用 engine.measure() 并保持当前档（或夹紧索引后 snapTo）。

P1-4

detent:content 只量内容区 scrollHeight，漏掉把手/标题/底栏高度，内容被裁出滚动条

P1

证据

engine.ts L210：contentH = getContent()?.scrollHeight；L133：最高档 h = Math.min(h, contentH)；L220：面板高度 = hiddenY - snapYs[0]。
ModalSheetCore.tsx L209–L225：把手 + header + content(flex:1) + footer 共享面板高度。

demo 02 的短内容场景：内容区测出 180px，面板也只给 180px，但把手+标题已占 ~64px，内容区实际只剩 116px。

后果

  • 「内容多高，弹层多高」的承诺不成立：短内容也出现内部滚动条，底部条目被裁。
  • 带 FooterPlugin 时更严重，按钮区挤占内容高度。

修复方向

改为测量「面板自然高度」：临时 height:auto 读 panel.scrollHeight（或 content.scrollHeight + 各 chrome 子节点 offsetHeight），再夹到视口/maxHeight；补 demo 02 的 3 条/12 条断言。

P1-5

ScrollLock / FocusTrap 只在 isOpen 翻转时清理，打开状态卸载会永久锁死 body、泄漏键盘监听

P1

证据

ScrollLockPlugin/create.tsx L33–L61：只有 onPropsChange，无 onUnmount；锁滚写 body.style.overflow。
FocusTrapPlugin/create.tsx L40–L81：keyHandler 只在 prev.isOpen && !next.isOpen 时移除。
withPlugins.tsx L126–L136：HOC 没有执行插件 onUnmount 钩子链。

后果

  • 路由切换 / 条件卸载 / demo 重挂（P1-1）时，body{overflow:hidden} 永久残留，整页无法滚动。
  • document 上的 Tab 监听不释放；多实例叠加后焦点在错误面板里循环。
  • 焦点不会归还给打开前元素。

修复方向

HOC 卸载时执行 onUnmount 链；两个插件实现 onUnmount 清理（恢复 overflow、移除 keydown、restoreFocus）。补「open 状态直接 unmount」单测。

P1-6

首帧即 isOpen=true 时，依赖 onPropsChange 的插件全部不启动

P1

证据

withPlugins.tsx L131–L136：prevPropsRef.current 首帧为 null，直接跳过 onPropsChange。
受影响：ScrollLock、FocusTrap、KeepMounted、History。
selftest.tsx L121–L134 正是 isOpen 常量初值 → focus trap 实际未激活，但自测仍 PASS。

后果

  • 首屏即开的引导弹层：背景不锁滚、焦点不进面板、不 pushState。
  • selftest 给了「FocusTrap 已验证」的假绿灯。

修复方向

HOC 挂载时以合成 prev（{...props, isOpen:false}）跑一次 onPropsChange，或让上述插件在 onMount 里按当前 isOpen 初始化。补首帧开启用例。

P1-7

插件工坊退化为静态清单，21 个插件里 13 个没有任何示例

P1

证据

PluginsPage.tsx L9–L72：只 map 出名称/priority/描述，无勾选、无预览、无 doc、无代码。
vane-profile PluginsPage L62–L266：勾选集合 → useMemo 装配 → 真跑预览 + 文档表 + 装配代码。
registry.ts L18–L32：仅发现 [0-9]*.tsx 六页；场景板仅 2 块。

后果

  • 用户无法验证「拔掉一个插件 = 拔掉一个能力」这一核心卖点。
  • ScrollLock / EscClose / History / Responsive / KeepMounted / ModalEffect / Haptics / Announcer / LoadingState / EmptyState / SafeArea / NestedScroll / FocusTrap 无可见示例。
  • README 只给 3 插件示例，20+ 插件只存在于源码树。

修复方向

工坊改成 vane-profile 四段式；示例按主题补 4 页（环境行为 / 无障碍与反馈 / PC 浮窗 / 加载空态），每个插件至少一处可触发入口。详见 58 清单 D 组。

P1-8

实施清单与仓库实际不一致：26→21、D 组 5 个勾完成但源码不存在、style.css 不存在

P1

证据

55-分析.md L76–L126 承诺 26 个插件（A/B/C/D 四面）；实际 src/custom-plugins 只有 21 个目录。
56-实施清单.md L42–L47：D 组 ListSelect/ActionSheet/Confirm/SharePanel/FilterPanel 与 E 组跨包组合均标 [x]，但仓库内无对应源码/包。
56-实施清单.md L19：声称产出 dist/style.css 与 exports["./style.css"]；实际 package.json L9–L113 无该导出，dist 也无该文件。

  • 发布说明若照抄 56，会对外承诺不存在的领域插件。

修复方向

二选一：补齐 D 组 5 个插件与样式产物；或修订 55/56 把范围收敛为 21 个并删除虚假勾选。推荐后者先做（本轮只做评审与清单，不改源码）。

06

安全审查

按 security-best-practices 的「可证实、可利用、本次代码引入」三原则，只报真实风险。

检查项结论依据
XSS / HTML 注入未发现全包无 dangerouslySetInnerHTML / innerHTML；Header title、children 均走 React 文本/节点。插件配置中的颜色只进 style 值，属于开发者可信输入。
全局副作用可恢复性有风险ScrollLock 直接改写 body.style.overflow，卸载不恢复（P1-5）→ 页面功能性拒绝服务。HistoryPlugin 卸载时 history.back() 属于无手势导航副作用（P2-7）。
事件监听泄漏有风险FocusTrap 的 document keydown 只在 isOpen 翻转时移除；打开状态卸载即泄漏（P1-5）。
history state 序列化低风险state?: unknown 直接 pushState；不可克隆值会抛 DataCloneError，属于健壮性问题而非安全问题。
SSR / 服务端执行需声明render 期访问 document.body，SSR 下抛错；应在 README 声明 client-only 或加 typeof document 守卫。
CSP 兼容已知取舍全部为内联 style，需要 style-src 'unsafe-inline'；这是零依赖 CSS-in-JS 的必然代价，应在文档说明。
第三方运行时依赖0无 motion / framer-motion，无供应链新增面。
07

React / 性能审查

按 vercel-react-best-practices 的核心原则：稳定组件类型、避免无谓渲染、把高频更新移出 React。

原则结论说明
不在 render 中创建组件类型违反demo 02–05 在函数体内调用 HOC 工厂（P1-1）。这是当前最高频的真实事故源。
高频值移出 React 渲染做得好拖拽逐帧只写 DOM transform + CSS 变量，不触发 React；时基值用 getter 而非快照。
context 稳定性基本稳定SlotProvider 用 useMemo；插件 context 为 getter 代理，无逐帧重建。
避免每次渲染跑副作用链违反onPropsChange effect 无依赖守卫（P2-4）；输入场景下 21 个钩子链每键重跑。
布局读取与写入分离可接受useLayoutEffect 打开时 measure 一次；每次 pointermove 只写 transform，不读 layout。
并发安全有隐患render 期改 propsRef.current（P2-12）；建议 layout effect 同步。
包体积预算内根入口声明 15KB 预算，子路径插件独立；但未实际复核产物大小，发布前需跑 check-packages。
