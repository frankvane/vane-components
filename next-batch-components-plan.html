02

目标模式：SOP 过筛 + 三条红线

五条判定来自 docs/guide/new-component.md。三条一票否决红线之上，选题视野扩到全平台形态——电商、社交、视频、直播、内容平台皆可立项，组件按通用业务引擎设计，不绑定单一行业。

1
核心职责薄且稳定
Core 只做渲染与生命周期转发，能力全部外置给插件，核心不膨胀。
2
需求长尾发散
能力点分散、可自由组合，适合插件化长尾生长，永不淘汰。
3
有清晰生命周期 / 事件
挂载、卸载、输入输出事件有明确时序，能映射到内核钩子。
4
有天然渲染插槽
存在 before / after / overlay 等插件可注入的渲染位。
5
按需加载能省体积
ESM 子路径导出 + tree-shaking，按需引入才有体积收益。
三条红线（逐条过筛，命中任一条即否决）：① 框架原子件不立项——Badge / Tag / Skeleton / Progress 等 UI 框架标配，内嵌为领域包积木；② 生态成熟专库不立项——react-window（虚拟化）、swiper（轮播）、emoji-mart（表情）、driver.js（引导）等已覆盖的引擎，直接选型接入；③ 架构不匹配不立项——核心价值在逻辑编排而非渲染插槽的 headless 引擎，插件内核收益低。
判定规则：红线先行，SOP 命中 ≥ 4 条即开工；下文 23 件候选全部命中 4–5 条、红线零命中。

05

开工前置事项（来自本次评审）

本次项目评审（详见会话中的评审报告卡片）确认 2.0 基线架构成熟，同时有三件事必须在新一批包发布前处理，优先级如下。

P0 · 立即
吊销并轮换 .npmrc 中的 npm 发布令牌
项目内 .npmrc 第 7 行含明文 _authToken，且 .lh/ 补丁记录中还有副本。吊销 → 凭据移到用户级 ~/.npmrc → .gitignore 增加 .lh/，然后才可继续发布。
P1 · 定案后开工
统一内核依赖策略（peer 外部化 vs 内联）
当前四个包两种策略并存，模板为 peer 声明。vane-sku 等新包从模板生成前必须定案，否则分裂会随每个新包扩散。
P2 · 顺手修
更新过时的“内核未发布”注释
vane-card 与 vane-file-preview 的类型注释仍断言内核“未发布到 npm”，与 0.1.0 已发布的现状相反；随第 1 批 PR 一并修正。
闸门 · 每包必过
发布闸门不降级
每包发布前 pnpm verify 全绿（类型 / 单测 / 体积红线 / demo 体检），changeset 随包提交；SOP 命中表写入各包 README。
